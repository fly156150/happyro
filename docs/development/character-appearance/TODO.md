# 职业外观 TODO

[职业外观总览](README.md) · [当前实现](implementation.md)

## 已确定的方向

采用通用、配置驱动的职业外观机制，首批开放十二条主职业线；诗人／舞娘分别验收，共十三个分支。机制不写死十二条线，后续普通职业通过增加映射配置与验证接入；新的特殊形态仍可能需要补充代码。开放指同职业线内选择经过验证的外观，不允许跨职业线任意换装。

本文件是待实施清单，取代原 roadmap.md，统一维护扩展计划；不表示以下功能已完成。当前已实现的内容与验证边界见[实现记录](implementation.md)。本功能尚未发布，不提供旧命令、旧变量兼容或迁移 SQL。

## 当前代码需要改造的部分

- 服务端 `src/common/character_appearance.hpp` 只识别骑士／十字军阶段，选项规则写死为六种外观。
- 地图服务的读取、更新和选项生成，以及角色服务的选角同步，均存在 `0～6` 范围限制。
- Admin 的 `CharacterMaintenancePayload` 同样限定 `between:0,6`。
- 客户端 `Renderer/Entity/CharacterAppearance.js` 写死六种显示职业与两条职业线的阶段判断。
- 外观选项仍依附大嘴鸟、龙、狮鹫的骑乘快照条目下发；面板通过骑乘条目寻找选项，普通步行职业缺少独立入口。

因此不能仅删除职业限制：必须同时补齐映射、下发、校验、渲染与预览。

## 实施清单

### 1. 职业与资源配置

- [ ] 核对十三个分支的真实职业 ID、阶段、性别、候选显示职业、身体资源和特殊形态，形成明确映射；不凭职业名称推断 ID。
- [ ] 定义配置中的外观标识、所属分支、可用阶段、性别条件、显示职业与特殊形态映射；默认外观使用明确的默认值。
- [ ] 明确每条线实际开放的阶段；沿用同分支向较早阶段选择的原则，当前阶段通过默认外观展示，不开放高于真实职业阶段的外观。
- [ ] 确定映射的权威来源及跨仓库同步方式，校验服务端、客户端和 Admin 数据一致，避免各自维护不一致的编号与范围。
- [ ] 只有核验通过的配置进入开放白名单；资源缺口与未验证组合保留为待办。

### 2. 服务端、协议与 Admin

- [ ] 将外观当前值与可选项从骑乘条目中独立下发；没有骑乘能力、没有骑乘技能或当前未骑乘时也能正常选择适用外观。
- [ ] 依据配置统一处理请求校验、保存值读取、职业变化后的重新校验，以及地图和选角同步，删除两条线与 `0～6` 的硬编码。
- [ ] 服务端作为最终资格校验方，拒绝未知编号、跨分支、越阶段及不适用性别的请求；Admin 更新参数校验，不通过简单扩大数字范围代替资格校验。
- [ ] 核对现有通知封包字段容量、默认值和选项标识的一致性；保持 PACKETVER=20211103 与两端封包设置一致，不因扩展配置无故更换封包编号。
- [ ] 保留 `character.appearance.update` 和 `HappyRO_CharacterAppearance` 命名；将外观职责从骑乘业务中拆出，错误语义与实际外观操作一致。

### 3. 客户端与显示

- [ ] 面板读取独立外观数据，按服务端允许的选项展示名称与当前选择，移除六个名称及骑乘条目依赖。
- [ ] 渲染层根据配置解析显示职业，替换两条职业线的阶段判断；真实职业仍决定技能、装备资格与属性。
- [ ] 先接入普通步行分支，再明确骑乘、骑狼、机甲、手推车和随行单位的显示规则；不因外观变化启用实际骑乘或改变随行单位身份。
- [ ] 同步更新选角、装备、他人装备与其他已有预览入口，保证默认、切换、恢复和资源加载失败路径一致。
- [ ] 保留并验证已有变身、第二服装等显示优先级，不把未核验组合自动放入首批范围。

### 4. 分批开放与验收

- [ ] 先用骑士／十字军验证通用机制没有回退，再逐批加入普通步行职业和特殊形态职业。
- [ ] 为下表每个分支记录开放选项、完成状态、测试证据与未覆盖组合；通过一条开放一条。
- [ ] 完成下方验收要求，并同步更新实现记录和对应产品仓库 changelog；客户端／服务端变更同步根仓库集中 changelog。
- [ ] 部署时配套更新服务端、Admin 和客户端；PWA 使用 `--all` 完整构建，并确认 Gateway 提供新产物后再进行实机验收。

## 验收要求

- [ ] 选择、恢复默认、非法跨分支／阶段请求，以及适用性别和资源组合分别检查。
- [ ] 真实职业、技能树、装备资格、属性、费用和实际骑乘／随行状态保持不变。
- [ ] 本人和旁观者实时同步；进出视野、切图、正常重登、死亡复活及默认路径回归。
- [ ] 对实际开放的外观检查移动、待机、攻击、受击、施法、武器附件和技能效果位置；步行与特殊形态分别记录。
- [ ] 三端选择入口、选角及装备预览检查；资源失败、超时、快速切换与迟到回调按现有规则回归。
- [ ] 证据记录实际版本、开放外观清单和未测组合；角色名称或身体资源加载成功不等于整线验收通过。

当前验证细节与已知限制见[实现记录](implementation.md)。新的实测结果与待办应随实际工作更新，原转职及技能审计的完成状态不迁移到本功能。
