# 同职业分支职业外观

状态：首版已实现（2026-10-18），目前开放骑士／十字军两条分支；机甲与骑狼仍待后续实现。下文保留整体边界，并记录首版实现及验收范围。

## 目标与边界

允许高阶职业选择同一职业分支以前的坐骑外观。允许人物服装随坐骑一起切换为旧职业外观，优先复用完整人物与坐骑动画，不制作人物、坐骑自由拼装系统。

外观与战斗状态分离：真实职业、技能树、装备资格、属性、骑乘费用和技能条件保持当前规则。例如龙骑士选择骑士骑大嘴鸟外观，实际仍是骑龙状态，可以使用原有龙息技能；这是外观选择，不是新增大嘴鸟战斗模式。

不开放跨职业分支混搭，不把只有代步用途的商城坐骑直接当作战斗坐骑。手推车不属于本方案的骑乘外观。

## 首版实现

入口为冒险工具「角色」中的独立「职业外观」区域，位于职业操作与骑乘随行之间，桌面、手机与平板共用组件。选择后立即生效：步行显示所选职业，骑乘显示其对应坐骑；不会自动租用或扣费。

| 当前职业 | 可选旧外观（另有「默认外观」） |
| --- | --- |
| 骑士领主 | 骑士 · 大嘴鸟 |
| 符文骑士（含进阶） | 骑士 · 大嘴鸟、骑士领主 · 大嘴鸟 |
| 龙骑士 | 上述两项、符文骑士 · 龙 |
| 圣殿十字军 | 十字军 · 大嘴鸟 |
| 皇家禁卫军（含进阶） | 十字军 · 大嘴鸟、圣殿十字军 · 大嘴鸟 |
| 帝国禁卫军 | 上述两项、皇家禁卫军 · 狮鹫 |

普通骑士、十字军没有更早阶段的战斗坐骑，因此不显示多余的外观选择框。婴儿职业不开放此功能。首版幻化使用原始配色，不改写已保存的服装染色；恢复默认后沿用原染色。第二服装、商城坐骑及变身按原有规则优先显示。

实现使用角色变量 `HappyRO_RidingAppearance` 保存稳定选项 ID（0 为默认，1～3 为骑士线，4～6 为十字军线），不新增数据库字段。`character.riding.appearance` 只接受外观选项，沿用角色维护权限、当前角色归属及幂等机制。服务端校验白名单并在转职时清理不合法选择。

独立通知 `ZC_HAPPYRO_RIDING_APPEARANCE`（`0x0d08`）为 8 字节：封包 ID、角色实体 ID、外观选项。不修改已有封包长度，`PACKETVER` 保持 `20211103`；客户端与服务端必须配套更新，旧页面需要刷新。

客户端增加独立 `renderJob`，不通过 `LOOK_BASE` 把旧外观变成真实职业。主体、武器、盾牌、披肩及攻击动作使用该外观解析；资源回调检查最新请求，避免旧结果覆盖快速切换后的状态。

通过本机 Gateway 读取 12 种外观的男女 SPR／ACT，共 48 个文件，均返回成功，文件头分别为 `SP`／`AC`；24 个 ACT 文件的动作入口数均为 104。

核验对象为候选表中的 8 种旧外观，以及 `DRAGON_KNIGHT2`、`IMPERIAL_GUARD2`、`MEISTER2`、`WINDHAWK2` 四种当前外观。路径按客户端 `DB.getBodyPath` 的性别目录和 `JobNameTable` 生成。

这仅证明主体资源存在、文件头及动作数量可读取，不证明所有方向、动作帧、武器、盾牌、头饰、披肩、染色或高阶技能画面均正确。没有修改或复制官方资源。后续实现应重新核验当时部署的运行资源，不依赖本次临时审查文件。

## 技术实现与约束

### 真实职业与显示外观分离（设计约束）

客户端目前在接收 `LOOK_BASE` 后会更新 `entity.job`，并刷新本人的职业信息及部分 UI；`EntityView.UpdateBody` 还会把骑乘职业编号反向映射成基础职业。因此不能直接发送旧职业编号充当外观切换，也不应通过通用伪装功能绕过职业判断。

已增加独立的骑乘外观选择与渲染状态，真实职业仍用于技能和界面判断。外观解析统一处理主体、武器、盾牌、动作与染色，避免各个渲染入口各自替换职业编号。高阶技能的攻击动作与特效起点必须在旧外观上核验。

### 服务端校验、保存与同步

- 服务端维护同分支、同阶段限制和可选外观白名单，客户端只提交稳定的外观标识，不提交任意职业编号或资源路径。
- 外观选择使用现有角色变量持久化；登录时角色变量在入图前加载，保存通过原有 registry 流程完成。
- 当前骑乘状态决定使用所选职业的骑乘或步行外观；下骑继续保留所选职业外观，选择默认外观才恢复真实职业显示。
- 转职后重新校验选择是否仍合法，不合法则恢复默认；职业变更与外观恢复必须使用同一解析规则。
- 本人及附近玩家都能看到选择；覆盖初次入视野、换地图、重登和实时切换，不能只刷新当前打开页面的人。
- 使用明确的外观同步数据，不复用无关字段。首版使用上述独立封包，保持 `PACKETVER=20211103`，不改变现有封包长度。
- 死亡、复活、下骑和重连时以服务端实际骑乘状态为准，不因外观选择自行添加或恢复骑乘状态。

### 特殊外观与切换优先级

优先级：游戏已有变身／特殊服装规则 > 骑乘外观 > 当前职业默认外观。特殊状态结束后重新解析外观，避免覆盖变身或永久残留旧外观。客户端按已有变身、服装与骑乘状态统一解析，不能靠刷新顺序偶然生效。

切换时处理异步资源加载的过期回调，确保连续选择、下骑或换地图后，旧请求不会覆盖最新外观。

### 菜单入口

在冒险工具「角色」中独立显示「职业外观」选择区域，默认「默认外观」，选项只显示职业名称，如「骑士领主」；下方单独显示「骑乘外观：大嘴鸟／龙／狮鹫」，默认选项对应真实职业的坐骑。骑士与十字军分支的骑乘项目统一标为「骑乘」，确认弹窗使用骑乘／下骑文案，费用及技能条件仍按真实职业计算。三端共用数据与交互，布局遵循现有公共 UI 规范。

外观选择权限与当前骑乘管理的角色归属、权限校验衔接，不新增任意变身权限。允许未骑乘时切换；选择外观不会自动租用、扣费或改变骑乘状态。

## 默认路径隔离与失败回退（2026-10-18）

- 未选择幻化时沿用原主体加载、延迟服装更新和附件赋值流程，不启动幻化双文件等待或超时计时器；选择代次用于阻止切换前的回调覆盖切换后的外观。
- 幻化主体必须同时加载 SPR 与 ACT 才替换画面。任一资源失败或 8 秒未完成，在本地暂停该角色的幻化并恢复真实职业外观，不改写服务端保存的选择，不自动循环重试。需要重试时先选择默认外观，再选择目标职业。
- 切换选择、更新主体和移除角色会取消旧加载等待。切回默认后，旧幻化主体、附件与服装回调不能重新覆盖画面。
- 幻化附件使用武器资源兜底时保留真实装备编号，避免外观兜底编号污染后续真实装备外观。
- 7 个测试文件共 27 项通过，包括默认路径、SPR／ACT 失败、超时、迟到回调、步行／骑乘切换，以及已有装备预览、移动端预览、动作帧与 GR2 实体回归。自动化回归未代替真实游戏的复杂装备与技能组合验收。

### 职业判定审查

- NPC／任务脚本的 `Class`、`BaseJob`、`BaseClass`、`Upper` 由服务端 `pc_readparam` 读取 `sd->status.class_`／`sd->class_`；`eaclass()` 同样读取真实职业。
- 装备资格 `pc_isequip`、职业装备掩码与技能条件仍使用真实职业。本功能只写入独立角色变量，没有调用转职、伪装或修改服务端 LOOK_BASE。
- 客户端技能树仍读取 `Session.Entity._job`；任务窗口读取服务端任务数据。新增 `renderJob` 仅供主体和附件资源选择，外观基础职业仅用于攻击动画选择，未接入任务、技能资格或装备资格判断。
- 服务端视图职业也未被幻化改写，因此脚本通过 `getlook` 查询服务端外观不会读到客户端幻化职业。
- 结论来自代码链路审查及自动化回归，并非逐个完成所有任务。未发现幻化影响职业资格判断的路径，不能据此保证所有未知问题都不存在。

新增封包仍要求客户端与服务端配套更新；默认路径隔离不提供旧客户端的协议兼容。其他玩家使用幻化时，当前客户端仍需解析和显示其外观。失败回退只处理本功能资源故障，不掩盖原本的网络断线或默认资源缺失。

## 角色预览同步（2026-10-18）

选角页原本只有真实职业，没有保存的幻化信息。角色服务在角色列表后发送 `HC_HAPPYRO_CHARACTER_APPEARANCE`（0x0d09，8 字节：封包编号、角色 ID、外观选项），按当前账号批量读取角色变量并复用职业白名单。SQL 失败时仍可正常选角。客户端按角色 ID 更新三端共用选角实体，重复列表分页保留选择，重新登录清空旧会话缓存；职业文字仍显示真实职业。

装备、装备切换和试穿预览复用公共预览实体组件，传递外观与服装状态，并将其纳入缓存签名；更换预览时清理旧实体加载等待。查看其他玩家装备时，从当前可见的同名角色取得幻化状态；目标已离开视野时原装备封包没有幻化数据，仍显示真实职业预览，此限制尚未扩展协议解决。

其余审查：旧版装备窗口直接绘制本人实体，本身支持幻化；公会成员头像仅加载头部而非职业身体，不受影响；手推车、表情、物品图片和新建角色预览不是当前角色职业幻化入口。任务与职业名称不应替换成幻化职业。

客户端协议、预览缓存和外观渲染 20 项回归通过，角色服务及地图服务构建通过。新增选角封包需要刷新客户端，与服务端配套更新。

真实 Chromium 验证：测试角色保存骑士外观后重新登录，选角实体真实职业为龙骑士（4252）、渲染职业为骑士（7）、选择为 1，随后正常进图并恢复原选择 0；无页面脚本异常。快速返回选角尝试未成功，因此这次实机结论限于重新登录路径。
